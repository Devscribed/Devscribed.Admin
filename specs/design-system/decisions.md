# Design system decisions

Every decision in `packages/ds` that is worth a number, in the order it was made. The numbers
are cited from the code as `§n`, at the point the decision shows up.

**This is a reference, not a history.** Each entry says what is true *now* — where a decision was
later reversed or repainted, the entry is the outcome and the reasoning that survived, not the
sequence. The full argument for any of them lives in the component file; this is the index.

Three rules about the numbers, and they are the reason this file is useful:

- **A number is never reused**, not after the decision is revised and not if it is ever undone.
- **A decision that shows up in code cites its number there**, so a value nobody can explain has
  somewhere to be looked up.
- **A new number is assigned when the code lands**, never reserved in advance.

The four rules these decisions all sit under — layout, tokens, the accessibility floor, and the
boundary — are in [`packages/ds/README.md`](../../packages/ds/README.md).

## Decisions

| § | Where | Decision |
|---|---|---|
| 1 | `Button` | No `width: '100%'`. A button that cannot be narrower than its parent has no way to sit next to anything, and a control's own paint is the wrong place to decide how much of a row it takes. The two compositions that want a full-width button say so themselves: `ConfirmDialog` passes the width, `FormActions` stretches its slot with a grid (§63). |
| 2 | `Button` | Everything not destructured reaches the element — `...rest`, `ref`, `style` merged over the paint, the caller's `onMouseEnter`/`onMouseLeave` composed with the hover state — and `aria-busy` while `preloader` is set. A button that has swapped its label for "Signing in" is busy, and a reader has no other way to know. |
| 3 | `TextInput` | Everything reaches the `<input>`, the caller's `onFocus`/`onBlur` compose with the focus state, and `id` also wires the label's `htmlFor`, falling back to `useId`. A label that is not associated with its field is text that happens to sit above it. |
| 4 | `TextInput` | `errorId` / `hintId`, and a `hint` that shares the error's slot **and its geometry**. The ids make either node an `aria-describedby` target; the shared slot is what stops the field moving every time an error replaces a hint. Error wins when both are given. |
| 5 | `TextInput` | `trailing` — a control inside the field's right edge, with the field's own right padding widened to match, so a long value never runs under it. It is where a password reveal lives. Not combined with `description`, which splits the row into a grid. |
| 6 | `InfoBanner` | `...rest` and `style` reach the banner. A banner is an announcement, and `role="alert"`, `aria-live` and `data-testid` are how it announces and how a test finds it. |
| 7 | `InfoBanner` | `error` and `success` beside `info` and `warning`. `error` is `warning`'s paint under the name that says what it means; `success` is green. Its tint follows the same 10%-of-status rule the others use, so the value is derived rather than picked. |
| 8 | `Modal` | A real dialog: `role="dialog"`, `aria-modal`, `aria-labelledby` on the title, `Escape` to close, a `Tab` focus trap, focus returned to the opener, `initialFocusRef`, and a name on the close button. All four rules go together — a panel that only closes by click is one a keyboard user cannot leave. Shared with `ConfirmDialog` through `useDialogFocus` (§40). |
| 9 | `Icon` | `EyeIcon` / `EyeOffIcon`, exported as `Eye` / `EyeOff` and registered in the dispatcher. The set's rules are explicit enough to draw a new mark to: geometric, filled, `currentColor`, 12–24px, a `viewBox` matching the intrinsic size, no icon font. |
| 10 | `IconButton` | The glyph-only control: a bare mark in `--text-secondary` on no background, scaling to 1.1 on hover — **icon buttons scale, they do not fill**. The `label` and the 34px hit area are what make it a control rather than a picture. |
| 11 | `AuthLayout` | The signed-out shell: one centred card on the page well. Every value is the system's existing vocabulary — `--surface-well`, a `--surface-card` panel with a hairline and `--radius-l` and no shadow, headline-5 for the title. The footer sits *outside* the card, so a visitor learns one place to look for the cross-account link. |
| 12 | `Card` | The general content surface: white, a 1px hairline, the 8px workhorse radius, **no shadow**. A static card takes a border, not a shadow, until it is hovered — painting a lift on something that does not move promises a click that is not there. `clip` (default true) is what rounds an edge-to-edge `Table`'s corners, and is what a card hosting a `Select` popover must turn off. |
| 13 | `Sidebar` | **The navigation is content.** `items` replaces the default set wholesale, each entry carrying `href` / `testId` / `active`, with `onNavigate` for a router, `aria-current="page"`, `logoHref`, `onClose` and a name for the landmark. Two gaps came with it: a section title is a real `<button aria-expanded>` rather than a `<li onClick>`, and a section that becomes current opens itself. |
| 14 | `AppShell` | The frame's one breakpoint, plus a `sidebar` slot, `menuOpen` / `onMenuClose` and the scrim. Below the breakpoint the rail **becomes** the drawer, carrying `MenuDrawer`'s geometry — wrapping a second copy would put two of every nav row, `data-testid` and `aria-current` in the document. The switch lives in `base.css` and **width alone decides it**, so the server and the hydrated client agree at every size. |
| 15 | `Navbar` | `tracker` and an `account` slot, both replaceable, plus `onMenuClick` for the drawer and the height moved to `.ds-navbar` so 80px can become 60px below the breakpoint. |
| 16 | `AccountMenu` | A real `<button aria-haspopup="menu" aria-expanded>` over a `role="menu"`, `Escape` with focus return, and item objects carrying `testId` and `onSelect` beside the plain strings. `nameTestId` / `menuTestId` are the first statement of a rule this file repeats: **whoever draws a node owns its test id.** |
| 17 | `PageTitle` | `...rest`, and the title may be a node. A heading that has to tag a name and an email inside itself needs children rather than a string, and the `<h1>` needs to be reachable by a test. |
| 18 | `Table` | **It takes records, not cells.** Column objects (`label`, `key`, `render`, `flex`, `align`, `maxWidth`) beside a plain `string[]`, and records as rows beside `ReactNode[][]`, plus `rowKey`, `rowTestId`, `rowHref` and `onRowClick`. A linked row is a real anchor, so middle-click and copy-address work, and the pointer cursor is conditional — a list that goes nowhere must not claim otherwise. |
| 19 | `Badge` | `...rest` and `style`. A badge is often the only node on a row stating what a record *is*, so it has to be findable by a test and nameable to a reader. |
| 20 | `Chip` | One chosen thing, with a way to drop it — promoted out of `Select` so a screen that *shows* a chosen thing and one that chooses it draw the same object. `CrossIcon` moved into the icon module with it, because a cross defined inside `Select` would have had to be copied. The cross is a real `<button>` with a name, and the pointer cursor is conditional. |
| 21 | `Select` | **It is a real combobox.** A painted box with a click handler cannot be reached by Tab, walked with arrows, left with `Escape` or announced as anything, and an `isSearchable` prop on it does nothing. This is `role="combobox"` over a `role="listbox"` with a roving `aria-activedescendant`, a real text input when searchable, per-option `disabled` / `hint` / `testId`, and a message slot matching §4's. |
| 22 | `Popover` | **It is a real menu**: `aria-haspopup="menu"` over `role="menu"`, arrow keys, `Home`/`End`, `Escape`. A blocked row is `aria-disabled` and **still focusable**, never the `disabled` attribute — the whole point of showing it is that its reason can be read. Per-item `key` / `testId` / `disabled` / `description` / `onSelect`. The *drawn* reason later moved into a bubble (§62); the always-present one stayed. |
| 23 | `Preloader` | `...rest` and `style`. A loader standing in for a screen's content has to be findable by a test and announceable as `role="status"`; one that is neither is a picture of waiting. |
| 24 | `InfoBanner` | `onDismiss` / `dismissLabel`, drawing an `IconButton` (§10) at the trailing edge. A banner reporting a *state* goes away when the state does and needs no control; one reporting an *event* — which nothing later makes untrue — has no other way out. |
| 25 | `TextArea` | `TextInput`'s §3 and §4 on its twin: everything reaches the `<textarea>`, `id` wires the label, and `error` is the message itself rather than a boolean paired with a second prop. One prop cannot be set without the other, and only one of them could ever carry a node. |
| 26 | `SearchInput` | `...rest` and `style` address the `<input>`; `wrapperStyle` addresses the 44px positioning root the glyphs are pinned to. A caller placing this field in a row is sizing that box, not the input inside it. The clear cross is a real `<button>` with a name — it empties the field, which is an action. |
| 27 | `Card` | `titleAs`, defaulting to `h2`. A screen that replaced its captions with card titles is relying on them to *be* the outline under `PageTitle`'s `<h1>`, and a `<div>` is not in that outline. The paint does not depend on the element. |
| 28 | `EmptyState` | `...rest` and `style`. The one node on the screen saying why a list is empty is the one a test most needs to name, and the one that most often needs a `role`. |
| 29 | `Select` | `allowCreate` / `onCreate` / `createTestId` — a `Create "…"` row, offered when the query matches **no option at all**, not when it matches none *exactly*. The looser test offers `Create "Eng"` while `English` is in the list above it. The test runs over all options, so a name already chosen in a multi-select still counts as matching. |
| 30 | `Calendar` | The month grid, built on a rem scale so seven columns stay square while the type around them changes size. Three decisions the shape does not make for itself: the week start is the consumer's (it hands in `weeks`), leading and trailing cells are blank rather than greyed, and it is a keyboard grid — arrows by day and week, `Home`/`End`, `PageUp`/`PageDown`. Availability and the booking window are business rules and arrive as props. |
| 31 | `ToggleButton` | **It is one control, not two buttons.** A `role="radiogroup"` of two `role="radio"` segments with one tab stop and arrow keys that move and select. A reader met with "24h, button" then "12h, button" is told there are two actions rather than one choice with two answers. Per-segment `data-testid`, and a name for the group. |
| 32 | `Badge` | `info` and `warning`, solid and outlined. Two hues are all a person's active/inactive ever needed; a workflow with five states cannot be painted in two without one of them saying something false. `warning` is the one that does not take the solid treatment literally — white on the warning yellow is not a legibility trade-off but an absence of text, so the ink becomes `--text-primary`. |
| 33 | `TextArea` | `trailing` — a node at the end of the **label row**, not inside the field. A multi-line field has no unambiguous right edge to pin anything to; the label row is the one place above it whose height does not depend on the value, which is what lets an indicator appear and leave without moving the field. |
| 34 | `Table` | `busy`, `hideHeader` and `footer`. `busy` dims the rows and sets `aria-busy` **together**, so a filterable list gets one treatment instead of each screen dimming its own body and forgetting the announcement; the rows stay, because a table that collapsed on every keystroke would reflow the page for no information. `footer` sits in the row position the next page will occupy. |
| 35 | `TextInput` | `wrapperStyle` — style for the field's own box, which `...rest` and `style` cannot reach because they address the `<input>`. The same slot `Select` (§21) and `SearchInput` (§26) carry, for the same reason. The three are siblings and agree by design. |
| 36 | `Select` | `closeMenuOnSelect`, defaulting to `true` for multi as much as for single. Left open, a multi-select covers whatever sits under it with a list that has often just emptied. A caller that really is picking several at once passes `false`. |
| 37 | `Chip` | `trailing` — a node between the label and the cross, sitting **outside** the label span. That span ellipsises to one line, so anything put in it is clipped, and a control that drops a list is cut off at the chip's edge. Plus `removeTestId`, because the cross is drawn by the component. |
| 38 | `Button` | `as`, which is `'button'` or `'a'`. A `<button onClick={() => location.assign(…)}>` loses middle-click, copy-address, open-in-new-tab and the browser's own download handling, none of which any script gets back. This is §18's `rowHref` swap, on a button. A `disabled` anchor still paints disabled and gets `aria-disabled`. |
| 39 | `Chip` | `leading`, `removeDisabled` and `removeDescribedBy`. A chip that can be picked up needs a grip on the *other* side from the cross — a control that reorders next to one that deletes is a misclick waiting. A blocked cross is `aria-disabled` and still focusable, which is §22's rule on the control `Chip` draws for itself. |
| 40 | `ConfirmDialog` | §8's dialog semantics on the second shell, and the behaviour moved into `useDialogFocus` rather than copied — two copies are how the two drift apart. Plus `acceptTestId` / `declineTestId`, because this component draws both buttons. |
| 41 | `ConfirmDialog` | `busy` and `closeOnAccept`. A confirmation that starts work nobody waits on can dismiss itself; one that awaits a result the reader has to see cannot. `busy` spins the accept button and blocks both controls; `closeOnAccept={false}` leaves the dialog standing. |
| 42 | `BoardCard` | One draggable card: a name, when it is, and the two marks a column can put on it. The surface is `Card`'s (§12) and the hover is the pair §12 declined — which is not a contradiction but §12's own condition, since this card *is* a control. The name is `--font-size-s`, because a board is five 220px columns and the name is the one line that must never wrap. **Space picks the card up; `Enter` opens it** — a board whose cards activated on Space could not be dragged by keyboard at all. |
| 43 | `BoardColumn` | A `--surface-sunken` well holding white cards, which is `AppShell`'s arrangement one level down. **The head sits inside the well**, not above it in a card of its own: a column is not a card, it is the ground the cards are on, and its name is a label on that ground. It converts a pointer position into a slot index and hands it back; what a slot means is the caller's. |
| 44 | `Icon` | `FlagIcon`, drawn rather than typed. `⚑` is a dingbat character, and the set's rule is that an icon is an authored `<svg>`. The caller paints it; nothing in the glyph picks a hue. |
| 45 | `PageTabs` | **Tabs are buttons, not links.** A tab chooses what is shown; an `<a href="#">` that calls `preventDefault` and swaps a panel is announced as a link that goes nowhere. `role="tab"` inside `role="tablist"`, with `aria-selected`, `aria-controls`, one tab stop and arrow keys. Plus the object form, which is §18's shape: a bare `string[]` cannot give a tab a value distinct from its label, a test id, or the panel it controls. |
| 46 | `BookingLayout` | The public shell. It is `AuthLayout` (§11) with two changes, both the same fact about who the page belongs to: **no card**, because these screens compose their own; and **the wordmark is the caller's**, because a candidate booking with an organisation is looking at that organisation's page. Everything else is `AuthLayout`'s deliberately, so a candidate who comes back through their invite link lands on the page they recognise. |
| 47 | `FileInput` | The file field, later repainted by §73. |
| 48 | `Table` | `minHeight` in place of a flat height, 8px of vertical padding, and the header label truncated the way every body cell already was. A cell may hold two lines — a title over its chips, a name over an email — and a fixed height does not contain that content, it lets it paint over the row beneath. A one-line row is still exactly 70px. |
| 49 | `ToggleButton` | `width: '100%'` beside the 160px cap. A bare `max-width` collapses the moment a caller puts the control in a flex row: a flex item sizes to content and both segments are `flex-basis: 0`, so it shrinks to the width of "24h12h" with the chosen segment painting over its neighbour. |
| 50 | `Popover` | The item **label** never wraps; only its description does. Switching the whole row to `white-space: normal` so a description could wrap took the label with it, and "Delete vacancy" broke across two lines in a 160px menu. |
| 51 | `MenuDrawer` | **It hangs from the shell's navbar, not from a number.** A literal `top: 60px` is the mobile navbar height frozen into a constant, and above the breakpoint the navbar is 80. Plus a name and a test id for the close button, focus moved in and returned, `Escape`, and `inert` while it is sliding out. Focus is deliberately **not** trapped — like the rail, this is a panel a reader may Tab out of. |
| 52 | `TableToolbar` | `tabsLabel`, `tabsTestId`, `searchLabel`, `searchTestId` and `...rest`. A composition that renders a tablist and a search field and offers no way to label or tag either leaves every screen with an unnamed tablist and a field whose only description is its placeholder. |
| 53 | `Pagination` | Page controls, built from the system's *small* controls rather than a new vocabulary — the 36px target, `--radius-s`, a hairline, and the chosen page filled the way `Calendar` marks a chosen day. Three behaviours are its own: the middle pages compress into an `aria-hidden` `…`, the current page carries `aria-current="page"`, and **one page draws nothing at all**. |
| 54 | `Toast` / `ToastHost` | The transient confirmation plate, and the queue is the caller's. **Its values are deliberately literals, not tokens**: the plate floats over whatever page is underneath and has to look the same over all of them, so folding its `#757575` into `--text-secondary` would let a change to the app's ink restyle a thing that is not part of the app. Top-right; an untyped message is white and unmarked; clicking it dismisses it, and the × stays. |
| 55 | `Popover` | `portal` (default true), and the placement that comes with it. Positioned inside the trigger's box the panel is clipped by whatever scroller the trigger sits in, so on a scrolling list the last row's menu is the one nobody can reach — and `overflow: visible` on the cell does not fix it, because the ancestor doing the clipping is the scroller. `position: fixed` in `document.body`, re-placed on scroll and resize, and opened **upward** when it would run off the bottom. |
| 56 | `BackTo` | `href`, `...rest`, and the event handed to the caller's `onClick`. This really is a link — one destination, and it is the page the reader came from — so with an `href` the anchor is left alone and middle-click, copy-address and open-in-new-tab all work. |
| 57 | `Icon` | `CopyIcon`, drawn **filled**, joining the main set rather than the outline family. §67 is the one case that goes the other way, and it says why. |
| 58 | `PageTabs` | The underline is drawn on **every** tab and only painted on the chosen one, and the tab is a column rather than a `<button>`'s centred box. Rendering the bar conditionally made the strip 16px taller the moment a tab was picked, so every label in the row moved; a bar that is always there and sometimes transparent costs one element and holds the row still. |
| 59 | `Badge` | `status="neutral"` and `size`. Every other tone says something is *going* well or badly; a category, an assessed criterion and an interview length are none of those — they are labels on an object, and drawing `Middle` in the red that means `inactive` says something false about it. `neutral` is the recessed ground with a hairline, at regular weight. `s` is the density a label takes inside a table row. |
| 60 | `Table` | The last column's cap is **96px**. A column holding a 32px kebab needs only 80, but the heading over it is a real 16px semibold word and `Actions` is 62px of it — at 80px, minus 12px of padding each side, every list screen drew `Actio…`. No other column's share changes, because this one was already at its cap. |
| 61 | `useDialogFocus` | The close callback is read through a ref, and the effect depends on `open` alone. A dialog with a field in it re-renders on every keystroke, and with `onClose` in the dependency list the effect tore down and re-ran between one letter and the next — handing focus back to the opener and then to the close button. Typing into "New category" put the caret on the × after the first letter. |
| 62 | `Tooltip`, `Popover` | The dark bubble a blocked action gives its reason in, shown on hover **and on focus**. A native `title` is not keyboard-reachable in any major browser, so the one person who could not see why an action is blocked is the one without a pointer. The meaning stays in the tree at all times so `aria-describedby` always resolves; the bubble is only what a pointer or a ring brings to the surface. |
| 63 | `FormActions` | The row ends at the right edge in every alignment but `left`. `align="full"` widens the box and stops the slots stretching, and a flex row with nothing saying where they go packs them at the start — so every dialog drew `Cancel` and its primary against the *left* edge of a 520px modal. `leading` is the tell: pushing a destructive button left only reads as "pushed left" if everything beside it is otherwise right. |
| 64 | `FieldLabel`, `TextInput`, `TextArea`, `Select`, `FileInput` | `RequiredMark` — the trailing asterisk, and `required` on the four controls that draw their own label. A form where everything is required needs no marker; one where some things are and some are not does, and a form that only tells you which on submit is a form you have to submit to read. The mark is **always `aria-hidden`**: the requirement reaches a reader through the control's own `required`. |
| 65 | `EmptyState` | `children` is a node, not a string. An empty state whose only content is a sentence is a dead end, and the way out of it belongs *in* the state rather than under it. |
| 66 | `Card`, `--radius-xl`, `--shadow-card-soft` | `variant="panel"` — the *other* white surface: a 20px radius over a 120px-blur 5% lift, no border. The two are a scale decision, not a style one: a hairline is what separates a 300px box from the boxes beside it, and a section as wide as its column has nothing beside it, so the border becomes an outline drawn around the page. `--radius-xl` is numerically `--radius-pill` and deliberately not it — one is a control rounded until it is a capsule. |
| 67 | `Icon` | `CalendarIcon` and `PersonOutlineIcon` drawn as **outlines**, which is the opposite of §44 and §57 — and they were right about the marks they were deciding. This is the case they do not cover: the candidate card states three facts as a list, one glyph per line, and the middle one is already an outline. A filled calendar over an outline clock over a filled person is three marks, two of which read as active states. **What is being drawn is the set, not the glyph.** |
| 68 | `PageTabs`, `ToggleButton`, `Calendar`, `BoardCard` | `isKeyboardFocus` — the ring is painted for a keyboard and not for a pointer. `focus` fires on a pointer press too, so a ring painted on every focus leaves a glow sitting on a tab, a segment, a day or a card until something else is clicked. A ring answers *where will my next keystroke land*, and a pointer user is not asking. The fallback keeps the ring: an extra one is a cosmetic complaint, a missing one is a keyboard user with nowhere to look. |
| 69 | `Preloader`, `base.css` | The pulse keyframes live in the stylesheet, not in a module-scope `document.head.appendChild`. A side effect that runs once on whichever page first imports the component fails silently everywhere it does not run, and a loader whose dots do not move is indistinguishable from a screen that has stopped — which is the one thing a loader exists to rule out. |
| 70 | `--control-height`, `--border-width-control` | 44px and 1.5px, named. Every interactive control states both, and so does everything built to stand beside them. One name, so a control added later lands on the same line as the ones already there instead of on a number somebody copied out of a neighbour. |
| 71 | `Button` | `pressed` — the chosen one of a set, plus `aria-pressed`. Most buttons *do* something and none stay down afterwards, so a pressed state needs a paint of its own: painting it with `variant="primary"` made the chosen slot on a booking page look like the page's primary action while `Book`, a few rows below, looked the same. The paint is the emphasis colour at 12% behind ink in the colour itself — how a selected calendar day reads (§30). |
| 72 | `Calendar` | The day cell repainted, at `--control-height`. The selection is a **tint, not a fill**: a solid cell is right for a *range* where a run of days reads as one block, and wrong for a single date beside a list of times, where it became the loudest thing on a page whose primary action is a button below it. An unavailable day is not filled at all — a grey block on every weekend reads as a second kind of selection. |
| 73 | `FileInput` | Repainted as a row, plus `fileSize`, `onClear` and the message in flow. §47 drew it as `TextInput`'s sibling so a CV field would sit at the same height as the fields beside it; what that produced **looks like a field you can type in and is not one**. A `<label>` is the chooser, so the browser opens the picker with nothing scripted; the input stays focusable and stays the labelled control, so there is exactly one tab stop. |
| 74 | `fieldLabelStyle` | Exported. Every system input already renders this treatment; what was missing was a way for a screen to put a caption on the same line as the field labels beside it without copying four numbers into app code. |
| 75 | `MiniTracker`, `Navbar` | `...rest` on the pill, and `trackerTestId` to reach it. The one node in the bar that says a timer is running forwarded nothing at all — no test could find it, no reader could be told what it was — which is rule 3's first clause, unmet on the component that most needs it. The prop is on `Navbar` because `Navbar` constructs the pill, which is `AccountMenu`'s `nameTestId` / `menuTestId` (§16) for the same reason. `tracker` stays a boolean and does not become a node slot: the pill is the same pill everywhere, and what differs between products is only whether there is anything to show. |
| 76 | `Sidebar` | `badge` and `badgeTestId` on a sub-item. A count on a nav row is *navigation content*, which §13 already says the rail takes from its caller — and a rail that draws every row but cannot draw the number on one leaves the screen to place a capsule over it from outside, against a layout it does not own. Falsy draws nothing: a pill reading `0` is a claim that there is something to look at. |
| 77 | `--font-family-mono` | A second family, for text the reader will **type or copy back** — a `{{placeholder}}`, a template's source, a key quoted in a message — where glyphs have to be told apart one by one and the width has to be even. A platform stack, so nothing is fetched for it. It is deliberately **not** the answer for numbers: a column of figures that needs to line up takes `font-variant-numeric: tabular-nums` on the base family, because a number in a report is not code and should not read as code. The system was silent here because it had never rendered either case; the silence was an omission, and the two halves of it want different answers. |
